# ESP Pinout Explorer roadmap

This table tracks the SoCs and related request from [issue #4](https://github.com/thelastoutpostworkshop/esp-pinout-explorer/issues/4). A profile is only implemented from official Espressif documentation; a package or board is not inferred from third-party pinout diagrams.

| SoC | Bare chip package information | Development-board information | Status / implementation notes |
| --- | --- | --- | --- |
| ESP32-S2 | [ESP32-S2 Series Datasheet](https://documentation.espressif.com/esp32-s2_datasheet_en.html), v1.9: top-view layout, pin overview, IO MUX, analog functions, restrictions, strapping, flash/PSRAM mapping, and QFN56 package data. | [ESP32-S2-DevKitC-1 User Guide](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s2/esp32-s2-devkitc-1/user_guide.html): header tables plus schematic, PCB-layout, and component details. | Ready. Implement the QFN56 package first, then the ESP32-S2-DevKitC-1 board profile. Preserve USB, Boot/Reset, UART bridge, RGB LED, and module-memory constraints as board warnings. |
| ESP32-C2 | Blocked for a bare-package profile. Espressif's [ESP-Docs link-check guidance](https://docs.espressif.com/projects/esp-docs/en/latest/configuring-esp-docs-projects/adding-link-check.html) identifies the ESP32-C2 datasheet as **not published**. The [ESP8684 hardware-design guidance](https://documentation.espressif.com/esp-hardware-design-guidelines/en/latest/esp32c2/index.html) is not a substitute for an official package pin table/layout. | [ESP32-C2 DevKits index](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32c2/index.html) documents ESP8684-DevKitM-1 and ESP8684-DevKitC-02; the [DevKitC-02 guide](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32c2/esp8684-devkitc-02/index.html) covers the official board. | Board-only candidate. Do not add a generic ESP32-C2 bare-chip profile until Espressif publishes its datasheet. If implemented, name the board profile ESP8684-DevKitC-02 or ESP8684-DevKitM-1, matching the official board and module markings. |
| ESP32-C61 | [ESP32-C61 Series Datasheet](https://documentation.espressif.com/esp32-c61_datasheet_en.html), v1.1: separate top-view layouts for QFN40 (HR2/HR8/HF4) and LGA40 (NF8R8LA), plus pin tables, warnings, strapping, and memory mappings. | [ESP32-C61-DevKitC-1 User Guide](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32c61/esp32-c61-devkitc-1/user_guide.html): J1/J3 header tables, component data, revision history, schematic, PCB layout, and dimensions. | Ready. Implement QFN40 and LGA40 as separate package variants. Model the board as ESP32-C61-DevKitC-1 v2.0; its header functions differ from v1.0. |
| ESP32-S31 | [ESP32-S31 Series Datasheet](https://documentation.espressif.com/esp32-s31_datasheet_en.html), v0.5 preliminary: QFN80 top-view layout, pin overview, IO MUX, warnings, strapping, and flash mapping. | [ESP32-S31-Function-CoreBoard-1 User Guide](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s31/esp32-s31-function-coreboard-1/user_guide.html): J2 header table and official schematic. [ESP32-S31-Korvo-1](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s31/esp32-s31-korvo-1/user_guide.html) is also documented. | Ready with a preliminary-data label. Implement QFN80 and the Function-CoreBoard-1 first; keep the exact datasheet version in source metadata and re-verify on a final datasheet release. |
| ESP8285 | [ESP8285 Datasheet](https://documentation.espressif.com/0a-esp8285_datasheet_en.html), v2.7: QFN32 layout, pin definitions, and integrated-flash constraints. Espressif marks the family NRND. | No specific, officially documented ESP8285 development board has been selected. | Chip-only candidate. Implement a separate ESP8285 QFN32 profile rather than reusing ESP8266EX: internal flash changes the availability and warnings for flash-connected pins. Add a board profile only after selecting an official board source. |

## Implementation rules

- Use the exact official package and board revision named above.
- Record source title, version, URL, and relevant sections in each profile.
- Add all official strapping, boot, flash/PSRAM, USB, UART, JTAG, reset, voltage, and on-board-hardware cautions.
- Run `npm run build` after each profile is added and verify package/board selection, search, warnings, drawer content, and mobile layout.
